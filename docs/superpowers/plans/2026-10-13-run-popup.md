# Run & record Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A **Run & record…** dialog in Tools → History that runs a typed command through `datalad run`, so the project records how a result was made; History already displays recorded runs.

**Architecture:** `run` becomes a curated command (schema + adapter + friendly errors). The main process confirms every run in a native dialog and honours an admin switch; the renderer adds a form overlay (same pattern as the identity dialog) whose pure logic lives in `run-dialog.js`. Cancel, live output and refresh reuse the existing run machinery.

**Tech Stack:** Node test runner (`npm test`), real-Electron e2e (`env -u ELECTRON_RUN_AS_NODE npm run test:e2e`, needs `datalad` + `git-annex`).

**Spec:** `docs/superpowers/specs/2026-10-13-run-popup-design.md`

## Global Constraints

- TDD (source-text tests count); zero new dependencies; vocabulary "save"/"version", never "checkpoint"/"commit" in UI text.
- Every value is bound to its flag (`--message=`, `--input=`, `--output=`) and the command follows `--`.
- No new write path outside `adapter:runCommand`; the renderer cannot run a command without the main-process confirmation.
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Claude cannot merge PRs; run `ponytail:ponytail-audit` before the PR; verify every claim about datalad/git with a real experiment (they were wrong twice before).
- CRLF-safe tests: read sources with `.replace(/\r\n/g, '\n')` (pattern in `test/diff-wiring.test.js`).
- Windows: `datalad run` goes through `cmd.exe` there; e2e commands use a script file (`node summarize.js`), never inline quotes.

## Review Focus

- A command with quotes, pipes, unicode or 10 000 characters, a message like `--amend`, inputs with spaces and globs: reach DataLad exactly as typed and cannot become options (Task 1).
- The user declines the native confirmation: nothing runs, no handle is left registered, the page shows a friendly "not run" result (Task 2).
- `policy.json` that exists but cannot be parsed: Run is disabled (fail closed), like the removed console (Task 2).
- The project becomes dirty between opening the dialog and pressing Run: DataLad's refusal becomes the "save first" message (Tasks 1 and 3).
- Cancel while the command runs: the process tree is gone, partial outputs are reported as unsaved changes, the dialog does not hang (Task 4, restored cancel e2e).

```js
const RUN_MAX_COMMAND_LENGTH = 10_000
const RUN_MAX_PATHS = 200

// Paths DataLad is told about: relative, inside the project (DataLad itself accepts "../x" silently).
function isProjectRelativePath(value) {
  return !value.includes('\0') && !/^([A-Za-z]:|[\\/])/.test(value) && !value.split(/[\\/]/).includes('..')
}

function assertRunRequest(request) {
  if (request.command.trim() === '') {
    throw new Error('Invalid request for run: command must not be empty')
  }
  if (request.command.includes('\0')) {
    throw new Error('Invalid request for run: command must not contain a NUL character')
  }
  if (request.command.length > RUN_MAX_COMMAND_LENGTH) {
    throw new Error(`Invalid request for run: command is too long (at most ${RUN_MAX_COMMAND_LENGTH} characters)`)
  }
  for (const field of ['inputs', 'outputs']) {
    const values = request[field]
    if (values === undefined) {
      continue
    }
    if (!Array.isArray(values)) {
      throw new Error(`Invalid request for run: ${field} must be an array`)
    }
    if (values.length > RUN_MAX_PATHS) {
      throw new Error(`Invalid request for run: at most ${RUN_MAX_PATHS} ${field}`)
    }
    for (const value of values) {
      if (typeof value !== 'string' || !value.trim()) {
        throw new Error(`Invalid request for run: each ${field} entry must be a non-empty string`)
      }
      if (!isProjectRelativePath(value)) {
        throw new Error(`Invalid request for run: ${field} must be paths inside the project`)
      }
    }
  }
}
```
